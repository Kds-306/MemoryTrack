Fastest Memory in JVM

Stack access is O(1) — just move a pointer. No GC, no scanning, no overhead.

🧵

One Stack Per Thread

Every thread gets its own private stack. No sharing, no race conditions — complete isolation.

📦

Stores Primitives Directly

int, double, char, boolean live IN the stack frame. No heap reference needed.

🗑️

Zero Garbage Collection

When a method returns, its frame is popped instantly. No GC pause, no cleanup thread needed.

What's inside a Stack Frame
01 / LOCAL VARIABLES

Local Variable Array

Stores all local variables declared inside the method — including the method's parameters. Primitives are stored by value; object references store the heap address.

02 / OPERAND STACK

Operand Stack

The JVM's scratch-pad for computations. When you write a + b, both values are pushed here, added, and the result stays on top.

03 / FRAME DATA

Frame Data & Return Address

Stores a reference to the runtime constant pool and the return address — where execution resumes in the calling method after this one finishes.

Common Stack Errors

StackOverflowError

Stack is full — usually caused by infinite or deep recursion. Each call adds a frame; eventually the stack runs out of space.

void infinite() { infinite(); } // boom

NullPointerException in stack

A local reference variable holds null but you tried to call a method on it. The reference is on the stack, the missing object was on the heap.

String s = null; s.length(); // NPE

Variable not initialized

Java doesn't default-initialize local variables (unlike fields). Using one before assignment is a compile error.

int x; System.out.println(x); // error

Scope escape attempt

Local variables can't outlive their frame. Returning a reference to a local object's value is fine; returning the local primitive itself is fine — the stack copy is returned by value.
